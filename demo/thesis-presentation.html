01 The gap

Career guidance tools tell students what they lack.
Almost none tell them how to get there — grounded in real demand.

Students struggle to align their skills with real job-market demand. Generic advising is disconnected from live data; when tools do use data or AI, they typically stop at diagnosis. Three recent systems define the state of the art this thesis was benchmarked against:

Weichselbraun et al., 2022

CareerCoach

Knowledge graph (734K edges) + course recommender, deployed at 3 Swiss/German firms. No persistent student model — every session starts stateless.

Ladkat & Bharati, 2025

MAS + LLM Career Planning

Four-agent LLM pipeline on local Ollama, full plan in <20s. Every recommendation is an LLM generation — no connection to real job postings.

José-García et al., 2022

C3-IoC

Deployed UK IT placement tool; asymmetric skill-gap metric + Louvain clustering. Diagnostic only — shows the gap, never a path to close it.

02 Research contribution

Five things no prior system in this comparison set does together.

Each of the three papers above solves part of the problem. CareerGraph's contribution is integrating all three capabilities — persistent state, ordered pathing, and market grounding — behind one architecture, plus two specific mechanisms none of them have.

Contribution 1

Persistent, proficiency-weighted student node

Students are first-class Neo4j nodes with HAS_SKILL {proficiency: 0–10, years} edges — not a session-scoped free-text blob. No comparator persists a proficiency-typed student profile at the graph level.

Contribution 2

Ordered roadmap via prerequisite graph traversal

LEADS_TO {difficulty_jump} edges + BFS + Kahn's topological sort produce a step-by-step acquisition sequence, not just a ranked gap list. Structurally absent from all three comparators.

Contribution 3

LLM as a decoupled, optional explainability layer

Four algorithmic agents compute every score deterministically; the LLM only narrates a result that already exists. It cannot hallucinate a gap score or fabricate a prerequisite — and the system runs fully with zero LLM configured.

Contribution 4

Continuous skill-normalization pipeline

Synonym map + rapidfuzz fuzzy matching (≥90 similarity) resolves surface-form variation without a fine-tuned NER model — directly answers the ~45% entity-linking miss rate reported by Weichselbraun et al.

Contribution 5

Live, re-ingestible knowledge base

A single admin endpoint re-ingests any CSV job corpus on demand. Unlike C3-IoC (frozen 2018–19) or an LLM's training cutoff, market intelligence reflects whatever was most recently ingested.

Positioning

Correctness and explainability are independent guarantees

Because the LLM sits strictly downstream of deterministic algorithms, a bad LLM day degrades wording, never numbers. This is a design property none of the three comparators can claim.

04 System design

Three tiers, seven agents, one orchestrator.

A React frontend talks REST+JWT to a FastAPI backend. The backend's Intelligence Engine dispatches to seven single-responsibility agents; a dual-database layer keeps ACID user data in PostgreSQL separate from the semantic graph in Neo4j.

Wraps any of the above in a plain-English explanation via Claude / GPT-4o / Ollama — template fallback when unconfigured.

05 The custom AI model

A trained GraphSAGE link predictor — separate from, and never touched by, the LLM.

The hand-tuned algorithmic agents above are formulas a human designed. The GNN is the learned alternative: a 2-layer heterogeneous GraphSAGE network learns a numeric embedding for every Student / Skill / Job / Course / Category node by repeatedly aggregating neighbor information, then predicts whether an edge should exist by comparing two embeddings. It is trained and evaluated as link prediction on two relations:

(Job) –REQUIRES→ (Skill)

Does this job posting require this skill? — the model's primary, most heavily-tested task.

(Skill) –LEADS_TO→ (Skill)

Is this skill a natural prerequisite toward that one? — evaluated on synthetic placeholder edges (see limitations, §07).

Why this is a legitimate thesis-level contribution

The literature review surveys knowledge-graph embedding approaches for this exact problem: de Groot et al. use Node2Vec for career-path link prediction; Vultureanu-Albisi et al. use TransE+GAT with knowledge distillation; Fettach et al. use TA-DistMult for temporal demand forecasting. None evaluate a personalized, per-student gap score with an apples-to-apples comparison against a hand-tuned baseline on identical held-out edges. That comparison — not a novel architecture — is the contribution here.

The GNN sits alongside, never inside, the LLM layer: the LLM is a pluggable, non-trained narration component; the GNN is the actual trained, structured-output-only model. Keeping them separate is itself a stated design decision.

Stated honestly — LEADS_TO has no real data source yet

Nothing in the ingestion pipeline produces genuine skill-prerequisite pairs — no dataset defines "Python leads to Machine Learning" style progressions. LEADS_TO edges are synthesized by a placeholder heuristic (same-category skills chained alphabetically) purely so the link-prediction task has something to train on for that relation. This is documented explicitly as a stand-in, tracked as Future Work — not presented as real curriculum data.

08 Training procedure

Leakage-safe split, honest negative sampling, 60 epochs, full-batch.

StepWhat happens
1. Edge splitEach target relation (REQUIRES, LEADS_TO) split 80 / 10 / 10 into train / val / test — per edge, not per node. Deterministic (seed = 42), independently unit-tested (ml/tests/test_split.py).
2. Leakage preventionHeld-out val/test edges are removed from the graph entirely before training — not just excluded from the loss. Message passing only ever sees train-split positives, so the model can't "see" a held-out edge's structure even indirectly.
3. Negative samplingFor every real edge, one fake edge is sampled and checked against the full positive set (train+val+test combined) — so a "negative" can never secretly be a held-out real edge.
4. Optimization60 epochs, Adam optimizer, learning rate 0.01. Full-batch: encode the whole graph once per epoch, score every train edge (pos + neg) via the dot-product decoder, backpropagate BCEWithLogitsLoss summed across both relations.
5. CheckpointingWeights, architecture config, node-ID↔index mapping, and full per-epoch loss history saved to ml/checkpoints/gnn_link_predictor.pt.

09 Evaluation — fair, identical test sets

GNN vs. the production algorithmic baseline, on the exact same held-out edges.

AUC-ROC — probability a random real edge outscores a random fake one (0.5 = chance, 1.0 = perfect). Hits@10 — fraction of real edges ranking in the top 10 against negative candidates. MRR — mean of 1÷rank across real edges; rewards the very best rank, not just top-10.

The fairness guarantee

The identical splits object is passed to both evaluate_gnn() and evaluate_baseline() in one function call — neither model can get an easier test set. The baseline itself is not a strawman: it reuses RecommendationAgent's exact production Jaccard / LEADS_TO-reachability formulas, imported directly, not reimplemented.

10 Reading the result honestly

The baseline still wins on REQUIRES, at 10×+ scale. That's the finding — stated, not hidden.

What the numbers actually say

REQUIRES: AUC-ROC narrowed to a near-tie (0.961 baseline vs 0.935 GNN), but Hits@10/MRR did not (0.116 vs 0.018, 0.067 vs 0.013). The candidate pool grew from 71 negatives to 5,429, which mechanically makes Hits@10 far stricter for both models — but more importantly, the Jaccard/co-occurrence baseline directly reuses ground-truth job-skill co-occurrence structure, and that advantage did not erode with scale the way the literature precedent (GNNs overtaking baselines "at scale") predicted it might.

LEADS_TO: the GNN's AUC-ROC rose substantially (0.306 → 0.685) with more skill-taxonomy structure to learn from — real progress. But the baseline still wins Hits@10/MRR outright (1.00/1.00) because it directly reconstructs the deterministic alphabetical-chain heuristic that generated the synthetic edges — tautological reconstruction, not generalization, and expected given LEADS_TO is still placeholder data.

What this section of the pipeline does prove

The full pipeline — export → leakage-safe split → negative sampling → train → checkpoint → evaluate → fair head-to-head comparison — is built correctly, reproducible (fixed seeds throughout), and now demonstrated at the intended thesis scale (9,380 jobs / 434 skills), not a small fixture. The defensible claim: the machinery is correct and proven at full scale; at this scale, a hand-tuned algorithmic baseline is a genuinely strong, hard-to-beat competitor for this specific graph and task — and the value delivered is the rigorous, reproducible comparison infrastructure that proved that, not a foregone "GNN wins" conclusion.

11 How it's wired into the live system

The GNN is optional infrastructure — the exact same pattern as the pluggable LLM.

Neither trained component is a single point of failure. The system — and its test suite — is designed to keep working correctly even if the model checkpoint were deleted or torch were never installed.

01

Never raises on construction

No checkpoint on disk, or torch not installed → is_available = False with a human-readable unavailable_reason, not a crash.

02

Returns None, never crashes

score_requires() / score_leads_to() return None when unavailable or for a node never seen at training time.

03

Fallback helper built in

score_requires_with_fallback() returns (score, source) — source tells the caller whether the number came from "gnn" or "algorithmic".

04

Verified by test

test_gnn_recommendation_agent.py (plain backend env, no torch) + a torch-env test asserting graceful fallback with no checkpoint.

13 Summary

What to take away.

01

Novelty is integration, not invention

Three prior systems each solve part of this problem well. CareerGraph's contribution is combining persistent state, ordered pathing, and market grounding in one coherent, tested architecture.

02

Correctness and explanation are decoupled

Every score is computed deterministically before the LLM ever sees it — the model can rephrase a result, never invent one.

03

The GNN is a rigorous comparison, honestly reported

A hand-tuned baseline still wins on REQUIRES at full scale — reported plainly, with the leakage-safe, fair-comparison methodology that makes that finding trustworthy.

04

Two named, scoped limitations

LEADS_TO is synthetic placeholder data; the dataset is realistic-scale but not real-world. Both have a concrete path to resolution, not hand-waving.

05

Built, not just designed

290 passing tests, a live 9,380-job / 434-skill knowledge graph, a trained & checkpointed model — every number in this deck is measured, not projected.

Future work

1) A real LEADS_TO data source — curriculum ordering or co-occurrence-plus-difficulty heuristics, replacing the alphabetical-chain placeholder. 2) Richer node input features (e.g. text embeddings of job descriptions) to test whether the GNN can close the REQUIRES gap. 3) Multi-seed evaluation (mean ± spread) to confirm the REQUIRES finding isn't split-fragile — lower priority now that it held up across a 71→5,429 test-edge scale-up rather than reversing.
