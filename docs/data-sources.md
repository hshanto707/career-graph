# Data Sources — Provenance Notes

> Companion to `system-design.md` §10 (Data Sources) and `features-todo.md` module B4.

## Current status: synthetic placeholders

`backend/data/kaggle_jobs.csv`, `backend/data/onet_skills.csv`, and
`backend/data/synonyms.json` in this repo are **synthetic, hand-generated
placeholder data**, not the real datasets. No live Kaggle account or O*NET
export exists in this sandbox/repo (checked `docs/` and `research-papers/` —
only PDFs). They exist so the ingestion pipeline (`IngestionAgent` /
`NormalizationAgent`), the admin ingest endpoints, and `seed_demo_data.py`
are fully exercised end-to-end, and so the test suite (`backend/tests/
test_ingestion.py`) has deterministic, realistic-shaped fixtures without any
network/API dependency.

They are clearly placeholders, now scaled up to meet the system-design.md
target:
- `kaggle_jobs.csv` has **10,000 rows** (target per system-design.md of
  10,000+ met). It was assembled by concatenating 10 domain-specific
  generator scripts in `backend/data/generators/` (`generate_*.py`, each with
  a fixed seed of `42 + <domain offset>`, e.g. software-eng, data-ai-ml,
  devops-cloud, business-finance, marketing-sales, product-design,
  project-ops, security-qa-support, healthcare-it, emerging-mobile),
  validating every row (non-empty fields, valid `type`, `salary_min <
  salary_max` as positive integers, >=2 skills), dropping any row that
  failed (0 rows dropped in the current build), de-duplicating exact
  `title+company+location+skills_required` matches (0 duplicates found
  across the 10 chunks), topping up with 700 additional rows regenerated
  from the software-eng generator at a different seed offset (`42 + 777`) to
  clear the 10,000-row bar after validation/dedup, and finally shuffling the
  combined set with a fixed seed (42) so the 10 domains are interleaved
  rather than sitting in contiguous blocks. The prior ~200-row fixture is
  preserved at `backend/data/kaggle_jobs.small_fixture.csv.bak` for anything
  downstream that still wants the tiny version.
  - Summary stats over the final 10,000 rows: 916 unique companies, 36
    unique locations, 732 unique skills referenced. Job-type distribution:
    Full-time 64.1% (6,410), Internship 16.7% (1,669), Contract 10.2%
    (1,017), Part-time 9.0% (904).
- `onet_skills.csv` has ~140 rows (target is 500+).
- `onet_skills.csv` was generated by a one-off local script (not checked
  into the repo, since it's a generation utility, not application code)
  using a fixed random seed, covering realistic skill names/categories.
  The `kaggle_jobs.csv` generators above additionally include a handful of
  deliberately malformed rows and synonym/typo variants (dropped or
  normalized as described above) so the red/green tests in
  `docs/test-plan.md` §B4 have real fixture material to exercise (dropped
  rows, exact synonym matches, fuzzy-match boundary cases, duplicate/
  whitespace-y skill fields).

## Real datasets to fetch before production ingestion

Per `system-design.md` §10 ("Primary Sources"):

1. **Kaggle Job Postings dataset** — 10,000+ real job postings.
   - Recommended source: search Kaggle for a current, actively-maintained
     "job postings" / "LinkedIn job postings" dataset (e.g.
     `https://www.kaggle.com/datasets/arshkon/linkedin-job-postings` or
     an equivalent Indeed/Glassdoor-scrape dataset with the same shape).
     Kaggle dataset URLs and their content change over time — verify the
     exact dataset slug at fetch time and record it here once chosen.
   - Required column mapping onto `IngestionAgent`'s expected schema
     (`title, company, location, type, skills_required, salary_min,
     salary_max, category`): most Kaggle job datasets do **not** ship a
     clean `skills_required` column — a skill-extraction pass (keyword
     matching against the O*NET taxonomy over the job description text) is
     needed as a pre-processing step before this pipeline's CSV reader can
     consume it directly. That extraction step is out of scope for B4 and
     tracked as follow-up work.

2. **O*NET / ESCO Skill Taxonomy** — canonical skill names + categories.
   - O*NET: `https://www.onetcenter.org/database.html` — the "Technology
     Skills" and "Skills" flat files give canonical skill names; O*NET does
     not ship a single flat "skill taxonomy CSV" — it must be derived from
     the O*NET database's `Technology Skills.txt` / `Skills.txt` tables.
   - ESCO (alternative/EU taxonomy): `https://esco.ec.europa.eu/en/use-esco/download`
     — download the "skills" CSV from the ESCO classification, which does
     ship a flatter `skill_name` + `category`-like hierarchy closer to what
     `NormalizationAgent` expects.
   - Whichever is chosen, regenerate `onet_skills.csv` with the same two
     columns (`skill_name,category`) this pipeline already expects, and
     regenerate/extend `synonyms.json` with any new common aliases observed
     in the real Kaggle skill text once it's available.

3. **Internshala scraper (optional, §10 "Optional")** — ~500 Indian job
   market postings, activated via an env flag. Not implemented in this
   phase; if built, its output must also be shaped into the same CSV schema
   before hitting `IngestionAgent`.

## Regenerating the placeholder fixtures

The generation script used a fixed seed (42) and is not part of the
application — if you need to regenerate a similarly-shaped placeholder set
(e.g., to add more edge cases), recreate a small script that:
- Writes `onet_skills.csv` with header `skill_name,category`.
- Writes `synonyms.json` as a flat `{alias: canonical_name}` JSON object,
  where every `canonical_name` value exists in `onet_skills.csv`.
- Writes `kaggle_jobs.csv` with header
  `title,company,location,type,skills_required,salary_min,salary_max,category`,
  including a few deliberately malformed rows (missing title/company/skills)
  and a few rows with synonym-form/typo skill names so ingestion tests keep
  covering every normalization branch.
